When you connect an account, Dialtu asks **how you want to onboard it**. The choice matters: it
determines whether you can keep using the WhatsApp app on the phone.

## The two options

<CardGroup cols={2}>
  <Card title="Cloud API" icon="cloud">
    A new number, dedicated to the platform. Full performance.
  </Card>

  <Card title="WhatsApp Business App (Coexistence)" icon="mobile">
    Keep using your current number and your everyday app.
  </Card>
</CardGroup>

## Comparison

| | Cloud API | Coexistence |
|---|---|---|
| **Can I keep using the phone app?** | No | **Yes** |
| **Is history synced?** | No | Yes |
| **Send throughput** | Full | Capped at **20 messages per second** |
| **High-volume outbound campaigns** | Recommended | Less suitable |
| **Maintenance** | None | The app must stay installed and be opened at least **once every 14 days** |
| **Best for** | A new number dedicated to automation | A number your team already uses daily |

## Which to choose

<Tip>
  **Choose Coexistence** if your team already uses the number from the phone and you don't want
  to lose that way of working. This is the common case when automating an existing number.

  **Choose Cloud API** if you're dedicating a new number to automation, especially if you plan
  high-volume outbound campaigns.
</Tip>

<Warning>
  **Coexistence requires keeping the app alive.** If the phone is lost, wiped, or simply nobody
  opens the app for more than 14 days, the connection can drop. If nobody on your team will use
  that phone regularly, Cloud API is more robust.
</Warning>

## Changing mode later

The connected account's detail view has a **Change onboarding mode** button.

<Note>
  If you don't see this window when connecting and go straight to Meta, your account is enabled
  for **Cloud API** only. Contact support if you need Coexistence.
</Note>
